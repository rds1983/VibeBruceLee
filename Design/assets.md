# Assets

All runtime assets live under `VibeBruceLee/Assets` and are copied to `Assets` next to the executable (`PreserveNewest`). README files stay in the repository and are not shipped. The game has no MonoGame content pipeline: XNAssets reads the raw files, and FontStashSharp renders text directly.

## Folder layout

```
art/       Sprites, tiles and backgrounds
audio/     Sound effects and music
fonts/     TTF/OTF fonts for FontStashSharp
levels/    Chamber definitions (JSON; see `chambers.md`)
licenses/  License texts for third-party assets
```

Folder names are lowercase. Use the same casing on Windows and Linux; asset keys are case-sensitive.

## Asset keys

- Relative to the asset root, forward slashes only: `art/test-card.png`.
- Lowercase with digits, `.`, `_` or `-`; kebab-case is preferred.
- The extension is required.
- Avoid leading slashes, drive letters, `..` segments and absolute paths in game code.
- Keys go straight to XNAssets. It normalizes separators and also supports rooted, absolute and `..` paths; the conventions above keep our asset root self-contained and portable.

Examples:

| Use | Avoid |
| --- | ----- |
| `art/test-card.png` | `Assets/art/test-card.png` |
| `fonts/press-start-2p-regular.ttf` | `C:\Assets\font.ttf` |
| `levels/chamber-01.json` | `../secrets.txt` |

## Loading

The game uses the library types directly; there are no wrapper classes over XNAssets or FontStashSharp.

```csharp
var assets = AssetManager.CreateFileAssetManager(Path.Combine(AppContext.BaseDirectory, "Assets"));

var texture = assets.LoadTexture2D(GraphicsDevice, "art/test-card.png");
var fontSystem = assets.LoadFontSystem("fonts/press-start-2p-regular.ttf");

spriteBatch.DrawString(fontSystem.GetFont(16), "VibeBruceLee", position, color);
```

Callers own loaded textures and `FontSystem` instances and must dispose them. Keep the `AssetManager` alive for as long as the game loads assets so its cache stays useful.

## Asset generation

Art and audio are generated by the C# tool in `Tools/VibeBruceLee.AssetGen`. Images are encoded with StbImageNext's `PngEncoder`; audio is written as PCM16 WAV. No editor or external tool is required.

Regenerate from the repository root:

```sh
dotnet run --project Tools/VibeBruceLee.AssetGen -- VibeBruceLee/Assets
```

Omit the path to use the same default. CI checks that the committed PNGs decode to the generated pixels and that the WAV bytes match. PNG bytes can differ between platforms because the compressor is platform-specific; content is what matters.

Do not hand-edit generated PNG/WAV files. Change the generator instead. Fonts are the exception: they are third-party files with their own licenses (see below).

## Fonts

FontStashSharp loads TTF/OTF files from `fonts/`. The bootstrap font is Press Start 2P under the SIL Open Font License 1.1. If it is replaced, use another OFL-compatible font or generate a custom TTF with the same generator project, and keep the license text in `licenses/`.

## Failure diagnostics

XNAssets raises `AssetNotFoundException` with the resolved `AssetPath` when a key cannot be found. Decode and loader errors come straight from XNAssets or its decoders, with the resolved path in the call stack. There is no custom validation layer.

```
Asset not found: 'D:\...\Assets\art\missing.png'
```

A missing asset is a programming error and fails fast at load time rather than rendering a placeholder.

## Hot reload

Not implemented. XNAssets caches loaded assets, and invalidating the cache safely is not worth the complexity yet. Restart the game after changing assets. Revisit when the screen stack and editor workflow exist (T-010+).

## Character sheets

Character art is procedural first-pass pixel art in `Tools/VibeBruceLee.AssetGen/CharacterArt.cs`. Each sheet is a horizontal strip of frames; poses share a fighter body so animations stay coherent. Replace or refine it in T-053.

| Sheet | Frame size | Frames | Map |
| ----- | ---------- | ------ | --- |
| `art/bruce.png` | 16x24 | 20 | 0-1 idle, 2-5 run, 6 jump, 7 duck, 8-9 chop, 10-13 kick variants (running kick uses 12-13), 14-15 climb, 16 hit, 17-19 death |
| `art/ninja.png` | 16x24 | 10 | 0-1 idle, 2-5 run, 6-7 attack, 8 hit, 9 fall |
| `art/yamo.png` | 24x28 | 10 | 0-1 idle, 2-5 run, 6-7 attack, 8 hit, 9 fall |

Bruce wears a yellow gi with a black stripe; the ninja uses dark blue with a red headband; Yamo is the larger green wrestler.

## Audio

All sound effects are generated as mono 16-bit PCM at 22,050 Hz by `WavWriter` using square-wave sweeps, deterministic noise and short arpeggios. No third-party audio is used. Runtime playback goes through `GameAudio`, which loads the WAVs with XNAssets `LoadSoundEffect`; missing files, absent audio hardware or playback limits leave the game silent instead of failing. `AudioSettings` owns master volume and mute.

The generated set covers jump/land, chop/kick, hit/knockdown, death/respawn, lantern pickup, chamber exit, wizard fireball and wizard defeat. Optional title music is not implemented yet.

## Tiles and HUD

- `art/tiles.png` is a 32x8 atlas of four 8x8 tiles: brick, stone, vine, dark.
- `art/hud-life.png` and `art/hud-lantern.png` are 8x8 HUD icons.
- The title and chamber placeholders render Bruce, Ninja, Yamo, tiles and HUD from these assets.

## Rules

- All shipped art, audio and fonts are original or compatibly licensed. The 1984 game is reference only.
- Never commit reference maps, screenshots, sprites or music from the original.
- Third-party assets need a license that allows MIT distribution; keep the license text in `licenses/` and record it here.
- Generated assets come from source code in `Tools/`; keep the generator and its docs current.
- Keep asset files small; no build output or temporary exports.
