# Architecture

## Solution layout

| Project | Purpose |
| ------- | ------- |
| `VibeBruceLee` | Game executable. MonoGame DesktopGL, `net8.0`, nullable enabled. |
| `VibeBruceLee.Tests` | xUnit tests. References the game project; tests must not create a graphics device. |
| `Tools/VibeBruceLee.AssetGen` | Build-time asset generator (PNG/WAV). Not shipped. |

`VibeBruceLee.slnx` contains the projects. The game's `Assets/` folder is the runtime asset root and is copied to the output directory with `PreserveNewest`.

## Toolchain

- The SDK is pinned through `global.json` to .NET 10 (`latestFeature` roll-forward). The `.slnx` solution format requires SDK 9 or newer, and the README asks for SDK 10.
- The game targets `net8.0` for MonoGame compatibility; SDK 10 builds and runs it.
- `Directory.Build.props` enables nullable reference types, implicit usings, .NET analyzers at the recommended level, and treats warnings as errors.
- Formatting and style defaults live in `.editorconfig`: C# uses tab indentation; XML, JSON and YAML use two spaces.
- CI runs restore, Release build, generated-asset verification, and tests on Windows and Linux (`.github/workflows/ci.yml`).
- `Tools/VibeBruceLee.AssetGen` is a small console project that produces PNG sprites (StbImageNext) and PCM WAV audio.

## Host

`BruceLeeGame` is the MonoGame `Game` host:

- fixed timestep at 60 Hz (`TargetElapsedTime = 1/60`),
- default window of 1280x960, resizable,
- F11 toggles borderless fullscreen; Escape or gamepad Back exits,
- vertical sync enabled.

## Presentation and screens

- The game renders into a 256x192 `RenderTarget2D`.
- `Letterbox.Calculate` picks the largest integer scale that fits the window and centers the canvas, leaving black bars. Nearest-neighbor sampling keeps pixels crisp at every scale.
- Window resizes update the back buffer; the canvas size never changes.
- `ScreenStack` holds the title, chamber, pause and game-over screens. Only the top screen updates; all screens draw bottom-to-top, so the pause screen overlays the chamber.
- Screens receive shared fonts and textures through `ScreenContext`; the game owns and disposes them.
- SpriteBatch uses `SpriteSortMode.BackToFront` with `SpriteLayers` (background, world, overlay, UI) so draw order is explicit.
- `SpriteSheetLayout` validates frame grids and maps frame indices to source rectangles; `SpriteSheet.Draw` supports integer scaling, horizontal flipping via `SpriteEffects`, and layer depth.
- `AnimationClip` holds frame indices and a per-frame duration. `AnimationPlayer` advances deterministically on a fixed-step clock, loops or finishes, and exposes the current frame. The title and chamber placeholders animate the four-frame lantern.
- The title, chamber and game-over screens are placeholders until real gameplay replaces the chamber.

## Input

- `InputAction` is the shared vocabulary: movement, jump, attack, pause, confirm, cancel, fullscreen, sound and a temporary debug action.
- Default keyboard and gamepad bindings live only in `InputBindings.CreateDefault`. Screens and game code never check raw keys or buttons.
- `InputSystem` polls `KeyboardState` and `GamePadState`, computes held/pressed/released edges and keeps 120 ms buffers for jump and attack. Gameplay consumes a buffer with `ConsumeBuffered`.
- Analog sticks use a 0.5 dead zone; D-pad and keyboard aliases work alongside them.
- Losing focus clears all state and buffers. A gamepad disconnect/reconnect also clears the frame state so nothing sticks, and the next frame suppresses accidental presses from buttons held during the transition.
- `DebugGameOver` (G) is a temporary placeholder until real gameplay can reach the game-over screen.

## Assets

The project does not use the MonoGame content pipeline. Raw runtime files are copied from `VibeBruceLee/Assets` to `Assets` next to the executable; readmes are excluded. The game creates an XNAssets `AssetManager` and uses `LoadTexture2D`, `LoadFontSystem`, `FontSystem` and `SpriteBatch.DrawString` directly. There are no wrapper services. Missing keys raise XNAssets' `AssetNotFoundException` with the resolved path.

Sprites and audio are generated by `Tools/VibeBruceLee.AssetGen`, which emits PNG and WAV files from code. The title screen exercises both the test card and lantern textures plus FontStashSharp text. Hot reload is not implemented; restart after changing assets. See `Design/assets.md` and ADR-0002.

## Physics

- `PhysicsBody` owns position, size, velocity, grounded and current-vine state. Callers set the desired horizontal velocity and jump/climb velocity each frame; `PhysicsWorld` applies gravity and resolves movement.
- `PhysicsWorld` is a fixed 256x192 world with configurable gravity and fall-speed cap.
- Movement is split into sub-pixel substeps on each axis, so fast bodies cannot tunnel through thin platforms or walls.
- Solid platforms block from every direction; one-way platforms only catch a falling body crossing their top.
- Screen edges clamp bodies; the bottom clamp counts as grounded.
- Vines have vertical or horizontal orientation. Attached bodies ignore gravity and move only along the vine axis; leaving the vine rectangle detaches them.
- Physics uses float positions but no randomness, so identical input sequences produce identical results.

## Chamber data

Chambers are JSON files under `VibeBruceLee/Assets/levels`, described in `Design/chambers.md`. `ChamberLoader.LoadAll` deserializes them with `System.Text.Json` (strict unknown-field rejection), `ChamberValidator` checks geometry, types, duplicate ids and exit targets, and failures throw `InvalidDataException` with field paths. The current two files are format samples; M4 authors the real layouts.

## Testing

- `dotnet build VibeBruceLee.slnx`
- `dotnet test VibeBruceLee.slnx`
- `dotnet run --project VibeBruceLee` (add `--fullscreen` to start in fullscreen)

Unit tests cover letterbox math, screen-stack lifecycle, input actions and buffers, sprite-sheet layout, animation timing, chamber loading/validation, physics and collision, asset generation and type-level smoke checks. Anything requiring a window is verified manually and, later, through headless simulation (T-060).
