# Architecture

## Solution layout

| Project | Purpose |
| ------- | ------- |
| `VibeBruceLee` | Game executable. MonoGame DesktopGL, `net8.0`, nullable enabled. |
| `VibeBruceLee.Tests` | xUnit tests. References the game project; tests must not create a graphics device. |
| `Tools/VibeBruceLee.AssetGen` | Build-time asset generator (PNG/WAV). Not shipped. |

`VibeBruceLee.slnx` contains the projects. The game's `Assets/` folder is the runtime asset root and is copied to the output directory with `PreserveNewest`.

## Toolchain

- The SDK is pinned through `global.json` to .NET 10 (`latestFeature` roll-forward). The `.slnx` solution format requires SDK 9 or newer, and the README asks for SDK 10.
- The game targets `net8.0` for MonoGame compatibility; SDK 10 builds and runs it.
- `Directory.Build.props` enables nullable reference types, implicit usings, .NET analyzers at the recommended level, and treats warnings as errors.
- Formatting and style defaults live in `.editorconfig`: C# uses tab indentation; XML, JSON and YAML use two spaces.
- CI runs restore, Release build, generated-asset verification, and tests on Windows and Linux (`.github/workflows/ci.yml`).
- `Tools/VibeBruceLee.AssetGen` is a small console project that produces PNG sprites (StbImageNext) and PCM WAV audio.

## Host

`BruceLeeGame` is the MonoGame `Game` host:

- fixed timestep at 60 Hz (`TargetElapsedTime = 1/60`),
- default window of 1280x960, resizable,
- F11 toggles borderless fullscreen; Escape or gamepad Back exits,
- vertical sync enabled.

## Presentation and screens

- The game renders into a 256x192 `RenderTarget2D`.
- `Letterbox.Calculate` picks the largest integer scale that fits the window and centers the canvas, leaving black bars. Nearest-neighbor sampling keeps pixels crisp at every scale.
- Window resizes update the back buffer; the canvas size never changes.
- `ScreenStack` holds the title, chamber, pause and game-over screens. Only the top screen updates; all screens draw bottom-to-top, so the pause screen overlays the chamber.
- Screens receive shared fonts and textures through `ScreenContext`; the game owns and disposes them. `FrameInput` carries current and previous keyboard/gamepad state so screens can detect presses.
- The title, chamber and game-over screens are placeholders for T-010; real gameplay replaces the chamber in later tasks.

## Assets

The project does not use the MonoGame content pipeline. Raw runtime files are copied from `VibeBruceLee/Assets` to `Assets` next to the executable; readmes are excluded. The game creates an XNAssets `AssetManager` and uses `LoadTexture2D`, `LoadFontSystem`, `FontSystem` and `SpriteBatch.DrawString` directly. There are no wrapper services. Missing keys raise XNAssets' `AssetNotFoundException` with the resolved path.

Sprites and audio are generated by `Tools/VibeBruceLee.AssetGen`, which emits PNG and WAV files from code. The title screen exercises both the test card and lantern textures plus FontStashSharp text. Hot reload is not implemented; restart after changing assets. See `Design/assets.md` and ADR-0002.

## Testing

- `dotnet build VibeBruceLee.slnx`
- `dotnet test VibeBruceLee.slnx`
- `dotnet run --project VibeBruceLee` (add `--fullscreen` to start in fullscreen)

Unit tests cover letterbox math, screen-stack lifecycle, asset generation and type-level smoke checks. Anything requiring a window is verified manually and, later, through headless simulation (T-060).
